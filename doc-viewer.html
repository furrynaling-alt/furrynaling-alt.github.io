一、项目概述

1.1 项目定位

**科技是一个集下单、接单、管理、安全验证于一体的全栈服务平台系统。项目采用前后端分离 + 多服务独立部署的架构，前端为 H5 Web 应用并打包为 Android APK，后端基于 Node.js + Express/Koa 构建四端独立服务。

技术栈
  • 后端框架: Node.js + Express ** / Koa **
  • 数据库: MySQL + mysql2 驱动
  • 前端: 原生 HTML/CSS/JS + DCloud ** Runtime
  • 加密体系: Node.js crypto (RSA-**** + AES-***-***)
  • 部署: Linux + systemd 进程守护
项目规模
  • 后端代码总量: ~12,000 行
  • API 端点总数: 247+ 个
  • HTML 页面数: 35+ 个
  • 数据库表: 16 张
  • 独立服务: 5 个
  • Android APK: 2 个

2.2 Nginx 反向代理

前端通过 Nginx 反向代理将请求分发到对应的后端服务端口，基于请求路径进行路由匹配。前端统一请求 /api/* 路径，Nginx 根据路径前缀将请求转发到不同的后端端口。

2.3 RSA+AES 混合加密体系

系统实现了零侵入的全链路加密方案：

[RSA+AES 混合加密流程时序图 - 已脱敏]

所有 POST/PUT 请求自动加密，包括登录、发送验证码、礼品卡兑换、余额操作等，业务代码零改动。服务端每次重启时自动生成新的 RSA-**** 密钥对，确保密钥不固定。

3.2 **服务方端

服务端服务 server.js 约 3,173 行，提供 65 个 API 端点，是服务方接单和工作管理的核心服务。

核心功能

  • 接单系统：浏览可接订单、接单（支持队长/队员角色）、1分钟内免费取消
  • 游戏流程：开始游戏（3人直开 / 1-2人需老板确认或2小时自动解锁）、完成订单、申诉
  • 收益系统：订单收入（金额x30%）、提现、72小时审核期、罚金扣除
  • 聊天系统：订单聊天（支持群组模式、2小时后只读、头像栏显示+复制暗区ID）
  • 个人管理：头像上传、昵称修改、游戏ID修改、密码修改
  • 封禁系统：禁登封号 / 禁单封号、定时自动解封、封禁原因记录
多人接单机制：每个订单最多支持 3 名服务方同时接单，第一个接单者为队长（is_leader=1）。3人订单可直开直完，1-2人订单需老板确认或等待 2 小时自动解锁。所有服务方完成后自动结算。

**安全管控系统

**安全管控是平台的安全防护与版本控制中枢，包含以下子系统：

  • 版本检查：三重拦截机制（永久最低版本 > 强制更新 > 维护模式），*** 签名防篡改
  • 双端维护模式：老板端和服务端可分别开启维护，各有独立提示语

双因素审批系统

管理端实现了 dual-approval 机制，敏感操作（如余额大额调整）需二次确认。审批流程：创建审批请求 - 验证器扫码确认 - 执行操作，全程记录审计日志。

3.4 **验证器

验证器服务 server.js 约 737 行，提供 14 个 API 端点，是管理端的扫码审批前端。

核心功能

  • 扫码登录审批：管理端扫码登录时，验证器端人工批准/拒绝
  • 操作验证审批：敏感操作的二次验证
  • 礼品卡管理：创建带金额和过期时间的礼品卡，SHA256+盐生成 card_hash
  • 数据看板：转发管理端统计数据
HTTPS 支持：验证器提供独立的 HTTPS 服务，使用自签名证书，确保手机浏览器可以调用摄像头进行扫码。首次访问需点击"继续前往"接受证书。

4.2 财务结算机制

结算流程
  1. 老板下单时，金额从余额扣除（FOR UPDATE 行锁）
  2. 服务方完成订单后，收入 = 订单金额 x 30%（计入收入日志）
  3. 72 小时审核期（从第一个服务方完成开始计时，三人同步）
  4. 审核期过后，服务方可申请提现（余额转入）
  5. 服务方拒绝订单（1分钟后），扣除罚金（计入罚金记录）
  6. 老板取消订单（无人接单时），金额全额退还

5.1 离线资源策略

所有 HTML/CSS/JS/图片资源均打包在 APK 本地，仅 API 请求发往远程服务器。API 请求路径统一为 /api/* 和 /uploads/*，前端资源引用使用相对路径。

5.2 FLAG_SECURE 防截屏

系统在验证码界面和礼品卡兑换弹窗启用 FLAG_SECURE 防截屏保护，直接使用原生整数值 0x00002000（8192），而非 Java 反射获取常量，确保在所有 Android 机型生效。

经验教训：使用 Java 反射获取 FLAG_SECURE 常量在部分 Android 机型/DCloud 版本上返回 undefined，导致截屏拦截失效。解决方案是直接使用数值 0x00002000，绕过反射机制。

5.3 安全键盘

密码/验证码/金额输入框的数字按键位置每次随机打乱，实现银行式乱序功能，与 FLAG_SECURE 配合使用，防止截屏+按键记录组合攻击。

九、关键问题修复记录

9.1 FLAG_SECURE 失效问题

问题：使用 Java 反射获取 FLAG_SECURE 常量在部分 Android 机型/DCloud 版本上返回 undefined，导致截屏拦截完全失效。
修复：直接使用原生整数值 0x00002000（8192），绕过反射机制，确保所有机型生效。

9.2 CDN 加载失败问题

问题：JS 库从 CDN 加载在 APK 离线环境下导致功能完全失效。
修复：html5-qrcode、@zxing/library、qrcodejs 全部下载到本地 www 目录，禁止从 CDN 加载。

9.3 全局防截屏问题

问题：H5+ 应用所有 HTML 页面共享同一 Android Activity Window，依赖 pagehide/unload 事件清除 FLAG_SECURE 不可靠，导致全局防截屏。
修复：在每个页面加载时通过公共配置文件显式设置 FLAG_SECURE 状态，不依赖页面跳转事件。

9.4 聊天头像不显示问题

问题：聊天头像栏不显示，点击头像复制ID无反应。
根因：
  • 聊天面板传参错误，找不到匹配联系人
  • 两个复制ID函数冲突，后者覆盖前者
  • API 错误被 catch(e){} 静默吞掉
  • 服务器未重启，运行旧代码不含头像字段查询
修复：自动找第一个进行中订单、合并冲突函数、增加错误日志、重启服务器。

9.5 确认开始按钮无反应

问题：老板端"确认开始"按钮点击后无任何反应。
根因：confirmStart 函数使用了未定义的变量（值为 undefined），后端校验字段失败。
修复：将未定义变量改为全局已定义的登录用户对象。

9.6 相对路径引用问题

问题：子目录 HTML 文件引用根目录资源时使用文件名（如 config.js），导致资源加载失败。
修复：统一改为相对路径（如 ../config.js），28个HTML文件全部修正。

9.7 koa-connect 内存泄漏

问题：koa-connect wrapper 导致 ctx 泄漏。
修复：原生重写中间件，不再使用 koa-connect。
